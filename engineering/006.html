Complete pairwise geometry does not tell us everything about a matrix.

It tells us how its rows relate through inner products, lengths, angles, and distances. It does not, in general, determine the relationships among its labelled feature coordinates.

In Graph Wiring: Accessing more information via Feature-Space. A Constructive Separation and Conditional Coding Analysis, I construct two corpus/query states with identical complete row Gram matrices but different feature-space relationships. A predictor combining cosine similarity with graph-based energy proximity distinguishes those states. Under the paper’s specified noisy relevance law, that distinction improves expected Top-1 accuracy from one half to seven eighths.

This article follows that distinction through to a concrete accounting question. Here, “charging for the predictor” means including the number of bits needed to describe the prediction method in the total, rather than comparing only how many bits are needed to encode the labels it gets wrong.

Does the improvement still pay when we charge for the predictor that makes it possible?

For the conditional coding comparison considered here, it does. At 1,024 relevance labels, the ideal expected model-plus-residual lengths are 1,025 bits for the uniform predictor and approximately 621.61 bits for the dual-space predictor.

The graph predictor costs more to describe. Its residual costs sufficiently less to compensate.

Scope: this is a constructive separation and a conditional finite-family coding comparison, not a general semantic-retrieval benchmark. The standalone Python snippets are teaching examples written from the public mathematics. The round-trip and graph-reuse blocks are illustrative pseudocode. None of these blocks is an excerpt from the private implementation or a public package API.

1. The baseline is complete row geometry—not just cosine

Let \(A\) contain the candidate rows and the query. Its row Gram matrix is

\[G = AA^\top.\]

Now apply the same orthogonal transformation \(R\) to every row:

\[A' = AR,\qquad RR^\top=I.\]

Then

\[A'A'^\top = ARR^\top A^\top = AA^\top.\]

The complete row Gram matrix is unchanged.

Consequently, an observer given only that matrix cannot distinguish the original state from the transformed state. This is stronger than saying that a particular nearest-neighbour search or cosine ranking fails: every function of the same Gram matrix receives identical input.

The feature coordinates, however, remain labelled. Their relationships can change under the transformation even though the complete row geometry does not. That is the distinction the paper exploits.

The invariant can be checked with a standalone Python example using only the standard library. These toy vectors illustrate Gram preservation; they are not the paper’s relevance fixture.

from math import cos, isclose, sin


def gram(rows):
    return [
        [sum(a * b for a, b in zip(x, y)) for y in rows]
        for x in rows
    ]


rows = [(1.0, 2.0), (3.0, -1.0), (2.0, 4.0)]
c, s = cos(0.4), sin(0.4)
rotated = [(c * x - s * y, s * x + c * y) for x, y in rows]

before, after = gram(rows), gram(rotated)
assert all(
    isclose(a, b, rel_tol=0.0, abs_tol=1e-12)
    for old_row, new_row in zip(before, after)
    for a, b in zip(old_row, new_row)
)

This assertion establishes what the row-geometry observer cannot see. It does not yet establish a useful prediction advantage; that requires a target and a readout.

2. Read the same vectors as signals on a feature graph

Graph Wiring supplies another view of the corpus: a graph whose nodes are features rather than items.

With a feature-space Laplacian \(L\), a nonzero vector \(x\) can be evaluated through its Rayleigh energy:

\[E_L(x)=\frac{x^\top Lx}{x^\top x}.\]

The paper combines cosine similarity with proximity between the query’s energy and a candidate’s energy:

\[s_\alpha(q,x) = \alpha\,\operatorname{cos}(q,x) + (1-\alpha)\frac{1}{1+|E_L(q)-E_L(x)|}.\]

Here \(\alpha\) weights cosine. The feature graph is constructed from the corpus, without using relevance labels. The companion implementation uses a cosine weight of 0.72 for the two-feature separation and the coded predictor; the frozen-graph control discussed below uses 0.60.

The scalar blend is also small enough to illustrate directly. This standalone snippet accepts already-computed energies and translates the published score into Python:

def illustrative_score(cosine, query_energy, candidate_energy, alpha):
    if not 0.0 <= alpha <= 1.0:
        raise ValueError("alpha must lie in [0, 1]")
    proximity = 1.0 / (1.0 + abs(query_energy - candidate_energy))
    return alpha * cosine + (1.0 - alpha) * proximity


# Toy inputs demonstrate the endpoints of the blend.
assert illustrative_score(0.8, 0.2, 0.7, alpha=1.0) == 0.8
assert illustrative_score(0.8, 0.2, 0.2, alpha=0.0) == 1.0

Graph construction and energy evaluation sit outside this snippet. Its output is a ranking score; calibrated label probabilities come from the relevance law in the next section.

The important point is not simply that the score changes. It is that the feature-space readout can distinguish states that the complete row Gram matrix cannot distinguish. The construction and its assumptions are given in the public paper.

This does not create information from nothing. A program with unrestricted access to the original coordinates could reconstruct and simulate the feature-space computation. The separation concerns what remains accessible after the observation is restricted to row geometry.

That qualification matters: “beyond complete row geometry” is a precise claim. “Beyond all information in the embeddings” would be a different—and unsupported—claim.

3. Connect the distinction to a specified prediction task

The construction uses a synthetic relevance law.

Let \(Z\) denote the state, with both states equally likely. Let \(B\) be an independent noise bit:

\[B\sim\operatorname{Bernoulli}(1/8), \qquad Y=Z\oplus B.\]

The relevance label agrees with the state with probability \(7/8\).

An observer restricted to the row Gram cannot distinguish the states. Under this law, its optimal label probability is therefore \(1/2\).

A dual-space observer that identifies the state can instead assign probability \(7/8\) to the corresponding label and \(1/8\) to the other label. This yields the paper’s expected Top-1 accuracy of \(7/8\), against \(1/2\) for every row-Gram-restricted observer.

The distinction also appears in calibrated log loss. Define binary entropy as

\[h_2(p)=-p\log_2p-(1-p)\log_2(1-p).\]

The uniform predictor needs one ideal residual bit per label. The state-informed predictor needs

\[h_2(1/8)\approx0.543564\]

bits per label in expectation.

The conditional predictive advantage is therefore

\[1-h_2(1/8)\approx0.456436\]

bits per label, matching the paper’s conditional log-loss analysis.

These labels are a deliberately specified synthetic target. They are not evidence, by themselves, that the same improvement holds for arbitrary semantic relevance judgments.

4. Charge for the model before claiming the saving

A predictor with lower residual loss is not automatically the shorter description. Its model description must also be counted.

The finite comparison used here assigns:

  • 1 model bit to the uniform predictor;
  • 65 model bits to the dual-space predictor.

The 65 bits are the dual-space predictor’s model cost under this article’s specified coding scheme; they do not represent the size of its software implementation.

For \(m\) labels, the ideal expected totals are

\[L_{\mathrm{uniform}}(m)=1+m\]

and

\[L_{\mathrm{dual}}(m)=65+m\,h_2(1/8).\]

These are costs within the specified conditional coding scheme—not claims that the complete software implementation occupies 65 bits. The model headers and shared-decoder assumptions belong to the finite coding construction described in the paper.

The entropy term is an ideal expected residual length. The companion implementation uses an exact dyadic interval code whose finite-code overhead is less than two bits per nonempty block. Its expected encoded length therefore includes that overhead in addition to the ideal total above.

Here is a standalone calculation using only the Python standard library:

from math import floor, log2


def binary_entropy(p):
    if not 0.0 <= p <= 1.0:
        raise ValueError("p must lie in [0, 1]")
    if p == 0.0 or p == 1.0:
        return 0.0
    return -p * log2(p) - (1.0 - p) * log2(1.0 - p)


p = 1 / 8
m = 1024

residual_rate = binary_entropy(p)
uniform_bits = 1 + m
dual_bits = 65 + m * residual_rate
saving_bits = uniform_bits - dual_bits
first_winning_m = floor(64 / (1 - residual_rate)) + 1

print(f"Uniform: {uniform_bits:.2f} bits")
print(f"Dual:    {dual_bits:.2f} bits")
print(f"Saving:  {saving_bits:.2f} bits")
print(f"Saving:  {100 * saving_bits / uniform_bits:.2f}%")
print(f"First winning label count: {first_winning_m}")

Expected output:

Uniform: 1025.00 bits
Dual:    621.61 bits
Saving:  403.39 bits
Saving:  39.36%
First winning label count: 141

The resulting comparison is:

Labels Uniform ideal expected bits Dual ideal expected bits Shorter description
140 141.00 141.10 Uniform
141 142.00 141.64 Dual
1,024 1,025.00 621.61 Dual

At 1,024 labels, the expected saving is approximately 403.39 bits, or 39.36%.

The crossover has a straightforward explanation. The dual predictor incurs 64 additional model bits, then saves approximately 0.456436 residual bits per label:

\[L_{\mathrm{uniform}}-L_{\mathrm{dual}} = m\left(1-h_2(1/8)\right)-64.\]

The ideal expected description becomes shorter at 141 labels. This crossover does not include the finite residual codec’s overhead.

5. Both descriptions must recover the same labels

An expected codelength calculation is useful, but an executable coding demonstration should also enforce recovery.

Both decoders receive the same corpus/query side information and the same shared interpreter. Neither should receive hidden state identifiers or reference noise bits as an extra input. A decoder can recompute its prediction from the shared scene; an encoder can encode the difference between that prediction and the observed label.

The required round-trip contract is:

# Illustrative pseudocode, not executable package calls.
# Each decoder receives the code and the same corpus/query scenes.
uniform_code = encode_uniform(labels, scenes)
dual_code = encode_dual(labels, scenes)

assert decode_uniform(uniform_code, scenes) == labels
assert decode_dual(dual_code, scenes) == labels

The companion implementation includes this check. Its fixed seed-3407, 1,024-label reference fixture has 123 flips and checks the following unpadded lengths:

Description Model bits Residual bits Total bits
Uniform 1 1,024 1,025
Dual-space 65 544 609

These are reference values checked by the implementation, not a separately reproduced public benchmark. The standalone Python calculation above verifies the expected-length comparison; it does not implement the residual codec or reproduce this fixture.

The 609-bit fixture result and the 621.61-bit expectation answer different questions. The expectation averages over the stipulated noise distribution. An individual label sequence has its own residual realization and finite coding overhead. The fixture’s shorter result is not a replacement for the expectation.

Logical bit lengths and byte-packed sizes must also be reported separately. For these reference lengths, byte padding gives 1,032 stored bits for the uniform description and 616 stored bits for the dual description. Padding is a storage detail, but it still matters when reporting an actual stored artifact.

These packed sizes count the payload bytes only. The companion implementation supplies the logical bit length separately when unpacking; the number of labels comes from the shared scene list. Any framing metadata needed to transmit or store that logical bit length must be accounted for separately.

6. Graph reuse is a separate control

A feature-space advantage does not automatically establish that a new graph must be learned for every state.

That is why the experiment includes frozen-graph controls: hold the graph fixed and evaluate the transformed signals against it.

# Illustrative pseudocode, not a public package API.
fixed_graph = build_feature_graph(reference_corpus)

for corpus, query in paired_states:
    prediction = score_with_graph(
        corpus,
        query,
        fixed_graph,
        cosine_weight=0.60,
    )
    check_prediction(prediction)

The paper reports that a fixed feature-graph control also succeeds at the selected cosine weight of 0.60. Its conclusion is therefore access beyond row geometry—not the necessity of adaptive graph learning.

The companion implementation checks this distinction explicitly: the graph frozen from the original corpus fails to distinguish the two states at 0.72, but succeeds at 0.60. The coding fixture uses the corpus-derived graph predictor at 0.72.

There are also two distinct scaling checks to keep separate:

  • The companion example checks noiseless repeated prototypes, including graph reuse.
  • The paper reports a clustered Gaussian-contamination experiment with 768 items and 128–512 active features. At 384 features, the development-selected weight of 0.60 achieves expected Top-1 accuracy \(7/8\) on sixteen untouched paired instances.

Repeating a prototype verifies a scaling identity. It is not the same experiment as testing robustness under contamination. Neither control, by itself, establishes indefinite reuse across arbitrary production drift.

7. What the coding result does—and does not—establish

The comparison establishes a shorter conditional description of the same relevance labels within the specified model family.

Several boundaries are essential:

  • Corpus/query inputs are shared side information. Their transmission is not included in the reported totals.
  • The predictor header is charged, but the shared interpreter is not.
  • The target follows the stipulated synthetic relevance law.
  • The baseline is restricted to complete row geometry, not unrestricted coordinate access.
  • The result is a finite conditional coding comparison, not a measurement of universal Epiplexity or compression of an arbitrary executable.

In particular, the labels remain marginally fair. There is no contradiction between their one-bit marginal entropy and a shorter description conditional on informative shared inputs.

If those inputs must also be transmitted, their cost belongs in a different, larger accounting exercise. The conditional result must not be presented as unconditional compression of a fair label stream.

8. Why this matters for Genefold

The practical direction is to treat feature-space structure as something that may repay its construction and description costs through better downstream predictions.

This example demonstrates that repayment in a controlled setting. It makes the tradeoff explicit: a longer model, a shorter residual, and a calculable point where the latter outweighs the former.

At Genefold AI, our objective is to turn that principle into useful data- and LLM-operations infrastructure. The production question is whether the predictive benefit survives real workloads after accounting for graph construction, storage, scoring latency, maintenance, and drift.

The public snippets expose the invariant, the scalar scoring rule, and the coding arithmetic. The pseudocode states the recovery and reuse contracts. Graph-building internals, numerical certification, residual encoding and decoding, and production integration remain in the private implementation.

Once the advantage can be computed, the discussion becomes concrete: what information is available, what the predictor costs, and whether the residual saving survives that charge.
